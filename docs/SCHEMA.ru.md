# Схема предметных данных

Приложение ищет значения заранее заданных объектов. Оно не извлекает неизвестные
объекты из текста. Каждая группа — массив объектов с обязательным строковым `id`.
ID уникален внутри группы. Остальные поля необязательны: их можно пропустить или
передать `null`. Отсутствующие группы считаются пустыми.

Русские и английские названия полей равноправны. Можно использовать любой вариант,
но нельзя одновременно передавать два имени одного поля. Неизвестные поля вызывают
ошибку, чтобы опечатки в схеме не приводили к незаметной потере данных.

| Тип / группа в JSON | Английское имя группы | Поля: русское → английское |
|---|---|---|
| Юр Лицо (также ЮрЛицо) | `legal_entities` | ИНН → `inn`; ИМЯ_ЮЛ → `name` |
| ФизЛицо | `people` | Фамилия → `last_name`; Имя → `first_name`; отчество / Отчество → `middle_name`; дата рождения → `birth_date`; предыдущая фамилия → `previous_last_name` |
| Документ | `documents` | Тип → `document_type`; серия → `series`; номер → `number` |
| Отправитель | `senders` | ФИО → `full_name`; Должность → `position`; Название организации → `organization_name`; обратный адрес → `return_address`; email → `email`; ИНН → `inn` |
| Прочее | `miscellaneous` | номер вх письма → `incoming_letter_number`; номер дела → `case_number`; дата вх письма → `incoming_letter_date`; дата истечения предв ответа → `preliminary_response_due_date`; email для ответа → `reply_email`; адрес для ответа → `reply_address` |

Вариант `дата истеченияпредв ответа` из исходного описания также принимается.
Поле трактуется как дата окончания срока предварительного ответа, без вычисления
срока из других дат. Для обратной совместимости сохранены группа `cars` и поле
`documents.issue_date`.

## Формат значений

- ИНН — строка из 10 или 12 цифр; ведущие нули сохраняются. Проверяется формат,
  а не контрольная сумма и не существование организации.
- Серии и номера — строки, даже если содержат только цифры.
- Даты — `YYYY-MM-DD` либо `DD.MM.YYYY`. При поиске также распознаётся `DD/MM/YYYY`.
- Поля `email` и `reply_email` принимают любую строку, включая пустую и строки
  с пробелами, либо `null`. Формат email не проверяется.
- ФИО отправителя для морфологии задаётся как `Фамилия Имя Отчество` или
  `Фамилия Имя`. Если во входном значении уже стоят инициалы либо формат другой,
  сохраняется буквальный вариант без попытки угадать структуру имени.

## CSV-выгрузки

Команда `mark-batch --input export.csv` читает CSV с разделителем `;`.
Каждая запись обрабатывается отдельно, с текстом из `txts/<versionId>.txt`
рядом с CSV. Общую папку текстов можно указать через `--txts-dir`.
Для нескольких CSV повторите `--input`. Обязателен столбец `versionId`;
отсутствующие необязательные столбцы не создают объектов.

| Столбец CSV | Отображение в существующую модель |
|---|---|
| `Субъект страхования ФЛ` | JSON-массив: Фамилия, Имя, Отчество, Дата рождения, Предыдущая фамилия → поля физлица |
| Поля документа внутри ФЛ | Удостоверение личности → тип; Серия документа → серия; Номер документа → номер отдельного документа |
| `Субъект страхования ТС` | JSON-массив: VIN, Гос. номер, Номер кузова, Номер шасси → поля автомобиля |
| `Субъект страхования ЮЛ` | JSON-массив: ИНН → ИНН; Полное наименование → название (если пусто, Краткое наименование) |
| `ФИО подписанта документа` | ФИО отправителя; при отсутствии используется Отправитель, затем Контрагент для контрагента не вида ЮЛ |
| `Контрагент` | Название организации отправителя при `Вид контрагента = ЮЛ` |
| `Должность`, `Email отправителя`, `Адрес отправителя` | Должность, email, обратный адрес отправителя |
| `Порядковый номер`, `№ дела` | Номер входящего письма, номер дела |
| `Дата регистрации`, `Срок предоставления ответа` | Дата входящего письма, дата окончания срока ответа |
| `Email для ответа`, `Адрес для ответа` | Соответствующие поля прочих реквизитов |

Это явное отображение экспортного формата, а не произвольное определение моделей
через CSV. Остальные столбцы и вложенные поля (в том числе Страна, ОГРН,
недвижимость, счётчики объектов и содержание письма) не используются для поиска.
Если указаны оба названия ЮЛ, используется полное; краткое не добавляется как
отдельный объект или дополнительный псевдоним.

Пустые строки и `null` в необязательных полях означают отсутствие значения.
Номера и ИНН должны оставаться строками; ведущие нули сохраняются. Для срока и
даты регистрации дополнительно допускается время в формате
`DD.MM.YYYY HH:MM:SS` или `YYYY-MM-DD HH:MM:SS`; используется календарная дата.
Все отображённые значения проходят существующую валидацию предметной схемы.

ID объектов генерируются по позиции в массиве: `person-1`, `car-1`,
`legal-entity-1`, `person-1-document`; отправитель и прочие реквизиты получают
`sender-1` и `misc-1`. ID локальны для записи CSV. Результаты содержат `versionId`,
`source_csv` и `source_row`, поэтому одинаковые ID из разных записей различимы.
Номер записи учитывает заголовок как 1, а многострочное поле — как часть одной
записи. Если файл `<versionId>.txt` отсутствует, запись пропускается с
предупреждением в stderr. Если отсутствуют все тексты, результат — пустой массив.
Остальные ошибки останавливают пакет до записи результатов.

## Правила поиска

- Имя, фамилия и отчество физлица размечаются отдельно: `PERSON_FIRST_NAME`,
  `PERSON_LAST_NAME`, `PERSON_MIDDLE_NAME`. Например, `Иванову Ивану Ивановичу`
  даёт три отдельных фрагмента, связанных с одним `id`. Полное ФИО физлица
  отдельной меткой не размечается. В записи `Иванову И.И.` отмечается только фамилия.
  Текущая и предыдущая фамилии, имя и отчество получают падежные формы;
  прежняя фамилия маркируется как `PERSON_PREVIOUS_LAST_NAME`.
- ФИО отправителя использует тот же морфологический адаптер; метка —
  `SENDER_FULL_NAME`.
- У названий организаций, должностей и адресов нормализуются регистр,
  горизонтальные пробелы и варианты кавычек. Сокращения адресов и организационных
  форм автоматически не разворачиваются.
- ИНН допускает пробелы между группами цифр. Email сравнивается без учёта регистра.
  В служебных номерах игнорируются пробелы, но сохраняются `/` и `-`.
- Для номера дела вида `A41-20769/2025` (латинская `A` или кириллическая `А`)
  поддерживается также `A41-20769/25`, в обоих направлениях. Двузначный год
  трактуется как 2000–2099; остальные цифры должны совпадать. Все упоминания
  размечаются отдельно с исходными границами, в том числе при `--disable-fuzzy`.
  Это правило не применяется к номерам входящих писем и другим форматам номеров.
- Для ИНН, email, дат, адресов и номеров дела/входящего письма нечёткий поиск
  отключён: изменение одного символа может указывать на другой реквизит.
  Для ФИО, названий организаций и достаточно длинных должностей работает Bitap.
  Правила существующих автомобильных и документных идентификаторов сохранены.
- Распространённые значения вроде `директор` или `паспорт` считаются слабыми
  признаками: для принятия им нужно локальное подтверждение другими полями того же
  объекта. Равнозначные совпадения с несколькими объектами отклоняются как неоднозначные.
- Если один фрагмент одновременно содержит ИНН или название юрлица и отправителя,
  сохраняются обе роли. Для разных типов допускаются совпадающие интервалы;
  частичные пересечения обрабатываются обычным разрешением перекрытий.

## Сквозной пример

Демонстрационные значения находятся в
[`examples/real_objects.json`](../examples/real_objects.json), текст — в
[`examples/real_text.txt`](../examples/real_text.txt).

```bash
uv run entity-marker validate --objects examples/real_objects.json
uv run entity-marker mark \
  --objects examples/real_objects.json \
  --text examples/real_text.txt \
  --output examples/real_predictions.json \
  --evidence-output examples/real_evidence.json \
  --pretty
```

Пример даёт 23 принятые разметки для всех пяти типов. Совпадающие название
организации и ИНН сохраняются в двух ролях. Для импорта в Label Studio используйте
обновлённый [`labeling_config.xml`](../examples/labeling_config.xml).

`real_evidence.json` содержит тип, ID объекта, поле, способ сопоставления и исходные
смещения. Все смещения относятся к оригинальному тексту; нормализация и морфология
его не изменяют.
